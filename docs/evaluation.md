# Evaluation

Generated by `python bench/evaluate.py`. Embedder `all-MiniLM-L6-v2`, PostgreSQL with pgvector (HNSW, cosine). 481 memories for 30 simulated users; 420 questions, each worded differently from the memory it should find.

## Recall by retrieval mode

Facts, episodes, order numbers and changed facts are hit@1 within each kind of question. Hybrid mixes 0.8 of the scaled vector similarity with 0.2 of the scaled text score.

| Mode | Hit@1 | Recall@5 | MRR | Facts | Episodes | Order numbers | Changed facts | Stale answer first | Cross-user results | p95 ms |
|---|---|---|---|---|---|---|---|---|---|---|
| vector | 0.969 | 1.000 | 0.985 | 0.944 | 0.983 | 1.000 | 0.677 | 0.000 | 0 | 36.1 |
| text | 0.536 | 0.605 | 0.570 | 0.333 | 0.583 | 1.000 | 0.000 | 0.000 | 0 | 22.7 |
| hybrid | 0.955 | 1.000 | 0.968 | 0.894 | 1.000 | 1.000 | 0.548 | 0.000 | 0 | 25.6 |

## Why supersession matters

The same data stored append-only (no `subject`, so a new value does not replace the old one): on the 31 questions about facts that changed, hybrid recall puts the **outdated value first 29%** of the time and the current one first 55%; with supersession, stale first 0%, current first 55%.
